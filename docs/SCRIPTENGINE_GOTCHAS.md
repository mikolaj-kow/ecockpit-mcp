# ScriptEngine gotchas — live-verified contract

Every trap encountered while scripting e!COCKPIT's ScriptEngine, with the
rule that avoids it. **Machine-readable contract**: one row per gotcha,
stable IDs (`G-nn`) — reference them from code comments, commit messages
and TESTING.md rows. All rows are live-verified unless marked
*(stub-only)*.

| ID | Symptom | Root cause | Rule | Live evidence |
|---|---|---|---|---|
| G-01 | `getattr(obj, "member")` fails even for members that work | .NET interop wrappers reject `getattr` | Access members by **direct attribute syntax inside try/except**; never build dynamic probes on getattr | 2026-10-21, export reporter + device parameter work |
| G-02 | `dir(obj)` returns nothing usable | same wrappers hide their member list | Discovery via **CLR reflection** (`clr.GetClrType(obj).GetMethods()/GetProperties()`) or the ScriptLib stubs | 2026-10-21 device(32)/onlineapp(34) member dump |
| G-03 | `get_file_list_of_directory` / `download_file` / `upload_file` / `delete_file` "missing" | wrong object: the **project-tree device** (`EScriptDevice`) never has them — the file API lives on the `ScriptOnlineDevice` from `online.create_online_device()` | Resolve file/source-archive calls through `online.create_online_device()`; see `_create_online_device` ladder | 2026-10-21/22: AttributeError on EScriptDevice, then root listing worked via created device |
| G-04 | `onlineapp.source_download()` NREs | wrong object again: the source push lives on `ScriptOnlineDevice.download_source(bCompact, additional_items)` | Use the device-level `download_source`; keep the application call only as a last rung | 2026-10-21/22: application form NRE, device form is the stub-documented one |
| G-05 | `export_xml` rejects our reporter (`expected IExportReporter, got Object_1$1`) | exposure names: the interface is injected as **`ExportReporter`** (`ImportReporter` / `NativeExportReporter` / `NativeImportHandler` likewise) — the `I…` names are .NET type names, never injected | Subclass reporters from the injected name; executor resolves via `_export_reporter_base()` (ExportReporter → IExportReporter → object) | 2026-10-21 |
| G-06 | syntax errors under the engine | the relay/executor run **IronPython 2.7** | No f-strings, no py3-only stdlib; `.format()` everywhere; keep the py2/py3 dual helpers | repo-wide convention |
| G-07 | `SystemError`/`Exception: Object reference not set to an instance of an object` from an API that the CHM documents | engine-defect class: the CHM documents methods this build cannot execute (save_archive: all 6 bindings; onlineapp.source_download) | Record the verdict in TESTING.md + SCRIPTENGINE_API.md, keep a self-healing ladder in the executor, point at working alternatives; do **not** retry blindly | 2026-10-21/22 save_archive (6 forms), source_download |
| G-08 | relay alive but GUI frozen / clients time out | a script triggered a GUI dialog the relay cannot answer (PLC-dialog wedge hazard) | Set `system.prompt_handling = PromptHandling.LogSimplePrompts` once per process (`_headless_hardening`); never call UI-prompting APIs unattended | 2026-10-21 |
| G-09 | a read-only command **deployed code** to the PLC | plain `device.connect()` performs an implicit login-WITH-DOWNLOAD | All logins go through `_online_login`: `onlineapp.login(OnlineChangeOption, false)` — read-only paths prefer `Keep`, deploy paths `Try` → `Force` → `Never` → connect fallback | 2026-10-21: a plc_ls pushed days of untested code live |
| G-10 | `get_file_list_of_directory("/")` → "Get directory entries failed" | the runtime has no listable POSIX root; its working directory is the root | Probe `.` first (executor falls back `requested → / → /tmp → /PlcLogic → .`); report the probed dir in the result | 2026-10-22: `.` listed 7 entries incl. PlcLogic/ |
| G-11 | `source_download` NRE on a project with unsaved changes | the source packer requires a **saved** project | `project.save()` first (best-effort, as in cmd_source_download); a never-saved project needs one GUI FILE → Save As, then `project.save()` works forever | 2026-10-21/22: NRE dirty, fine saved |
| G-12 | `online.create_online_device(raw_device)` → `expected IExtendedObject[IScriptObject]` | `create_online_device` wants **no argument** (then the active application's device is used) or a device **ScriptObject** (via `project.find`) — not the raw interop device from `project.devices` | Use `_create_online_device` ladder: no-arg → ScriptObject by name | 2026-10-22 |
| G-13 | CHM documents members the live build rejects or lacks | the CHM is the generic CODESYS ScriptEngine reference; e!COCKPIT ships a **reduced/modified** API (and the ScriptLib stubs differ from the CHM in both directions) | Trust order: ScriptLib stubs → live probe → CHM; keep every deviation in this table and in SCRIPTENGINE_API.md | standing |
| G-14 | `save_archive` NREs in every binding — even with a saved, named project | project-level archive API is broken in this build (distinct from G-11: source_download only needed a saved project) | 6-form ladder + attempt log in `cmd_save_archive`; tool removed; `ecockpit_snapshot` is the backup path | 2026-10-21/22 |
| G-15 | UnboundLocalError when adding a new dispatcher branch | dispatcher-local `project` must be assigned (`get_project()`) before use in any branch that needs it | Regression-tested: `test_online_commands_reach_dispatch_without_unbound_project` | 2026-10-21 |
| G-16 | `warning() takes exactly 2 arguments (3 given)` during export | the EXPORT flow calls reporter callbacks with **two** message arguments (CHM documents one) | All reporter callbacks take `*argv` and log everything | 2026-10-21, live export |
| G-17 | `Access to the path '<dir>' is denied` on export | `export_xml`'s `path` is the path of a **FILE** we export into — never a directory | Target `<dir>/<name>.xml`; or call with `path=None` (whole XML returned as string) and write it ourselves | 2026-10-21: any directory refused |
